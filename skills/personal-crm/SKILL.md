# Personal Crm

## When to use
The user wants to remember people and follow through, using a file they control.

## Steps
1. Ask what keeps slipping and who is in scope. Start with a small list the user names; do not import a whole address book.
2. Choose a plain file such as CSV or one Markdown note per person, stored where the user decides. Ask before including cloud-synced or shared folders.
3. Keep few fields: name, how they know each other, preferred channel, last meaningful contact, next follow-up date, open promise, short notes.
4. Write the rule for notes: only what the person would be comfortable seeing. Leave out health, finances, sexuality, beliefs, gossip and others' secrets.
5. Set follow-up timing only for people where the user wants it, by relationship, with no scoring or ranking of friends.
6. Add each interaction as a dated line and update last contact and any promise.
7. For a weekly look, list overdue promises first, then due follow-ups and upcoming dates the user recorded.
8. Draft messages only on request, grounded in real notes; the user sends them.
9. Define deletion and export, and prune stale entries periodically.

## Watch out for
- Compiling information about people from the web or social profiles; this record holds what the user already knows first-hand.
- Business or customer contacts may fall under data protection law and employer policy; use the approved system.
- Long field lists that nobody maintains.
- Messages that quote private notes back to the person.

## Operating rules
- Look before you change anything: read the real files, data or page first.
- Report what you actually ran and saw; never invent results, sources or numbers.
- Ask before destructive, paid, public or irreversible actions.
- Never print, store or commit secrets or private personal data.

## Done when
The file exists in a location the user chose, holds only agreed fields, and can produce the list of overdue promises and due follow-ups.
