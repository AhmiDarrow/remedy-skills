# Daily Planning

## When to use
A day needs a plan, or the to-do list is clearly longer than the day.

## Steps
1. Read the day's events and any task file the user points to. Ask for working hours, hard deadlines and when they think best.
2. Work out free time: the working day minus events, travel, meals, and short gaps around meetings. Plan only about 60-70% of it; the rest absorbs overruns and interruptions.
3. Sort tasks by real consequence: due or costly if missed today; important but movable (give each a date); small items someone else could do; items to drop. A loud request is not automatically urgent. The same sort works for a longer project list: mark each do, schedule, hand off or drop, with a rough estimate and next action.
4. Rewrite vague items as a next action with a visible result: "report" becomes "draft the findings section".
5. Pick at most three must-finish items and estimate each. If they exceed the planned hours, say so and ask which moves or who needs to be told.
6. Place the hardest one in the best-energy slot. For each focus block name one output, a length that fits the gap, what gets closed or muted, who may still interrupt, and where to jot stray thoughts. Put real breaks between blocks. Start a block by setting up the desk and files it needs; end it by noting where to resume.
7. Batch messages and small admin into one or two slots.
8. End with a short shutdown: record unfinished items with their next step, check tomorrow's first commitment, and write tomorrow's first task. If they want a morning routine too, fit it to the minutes they actually have. For a lasting routine, agree device boundaries, try it for two weeks, then adjust.
9. Show the plan; create calendar blocks only after they approve.

## Watch out for
- Filling every gap guarantees failure by mid-morning.
- Silently dropping a deferred task. List it with its new date.
- Rebuilding from scratch after a disruption; keep the top item and re-fit the rest.
- Assuming mornings are best. Ask.

## Operating rules
- Look before you change anything: read the real files, data or page first.
- Report what you actually ran and saw; never invent results, sources or numbers.
- Ask before destructive, paid, public or irreversible actions.
- Never print, store or commit secrets or private personal data.

## Done when
The plan fits the free time with slack, has no more than three must-finish items, and every deferred or dropped task is listed.
