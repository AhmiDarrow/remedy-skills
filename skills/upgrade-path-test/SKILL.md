# Upgrade Path Test

## When to use
Fresh installs pass every test, while existing users carry years of old data that no test has seen.
## Steps
1. List persisted things: databases, config, caches, saved documents, credentials store entries, scheduled tasks, install locations.
2. Decide which old versions must upgrade directly: at least the previous release and the oldest one still supported, since migrations chain.
3. Create fixtures by running those actual released builds and using their features. Do it in a disposable VM or separate test account unless you have confirmed every path the build and its installer touch can be redirected to a scratch directory; otherwise an old build can overwrite the user's real install and data. Hand-written old data repeats your assumptions.
4. Include unusual states: empty, very large, custom settings, non-ASCII paths, half-finished operations. Use synthetic data only.
5. In that same isolated environment, upgrade a copy the way users do (updater or installer, not a developer command).
6. Verify content, not just startup: record counts, sampled values, settings preserved, features usable.
7. Interrupt a migration partway on another copy and restart; it must resume, roll back or refuse safely with the original intact.
8. Open already-migrated data a second time to confirm migration does not run twice.
9. Check what the old version does with new data. If it corrupts it, document that downgrade is unsupported or add a version guard.
## Watch out for
- Testing on your only copy of real data.
- Defaults silently replacing user settings when a key is renamed.
- Fixtures regenerated by the new code, which destroys their value.
## Operating rules
- Look before you change anything: read the real files, data or page first.
- Report what you actually ran and saw; never invent results, sources or numbers.
- Ask before destructive, paid, public or irreversible actions.
- Never print, store or commit secrets or private personal data.

## Done when
Fixtures from each supported old version upgrade with verified content, and interrupted and repeated migrations have been exercised.
