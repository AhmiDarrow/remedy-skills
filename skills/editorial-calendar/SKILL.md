# Editorial Calendar

## When to use
A person or team needs to schedule content production over a month or quarter.

## Steps
1. Collect the horizon, strategy themes, fixed dates such as launches, events and holidays relevant to the audience, ideas in the backlog and existing commitments. Read calendars if the user allows it.
2. Estimate work per format from the team's past pieces: research, draft, review, design, approval and publishing. Include waiting time for reviewers.
3. Count available hours per person after leave and other duties. If planned work exceeds them, cut or move pieces now.
4. Place fixed-date items first, then work backwards to set dates for brief, draft, review and ready. Spread each reviewer's load.
5. Give each item one row: title, reader and goal, theme, channel, one accountable owner, stage dates, status, dependencies and final link.
6. Define status exit conditions, for instance "ready" means approved, assets and alt text complete, links checked.
7. Keep open slots for timely work, plus a few evergreen pieces ready as substitutes. Mark which items drop first.
8. Set a short weekly check: late items, blockers, timing that has become inappropriate, and what to move.
9. Write the table in the format the team already uses. Create calendar events only after the user approves the list.

## Watch out for
- Publish dates with no production dates.
- "Team" as owner.
- Scheduled posts going out during an incident or tragedy; include a pause step.

## Operating rules
- Look before you change anything: read the real files, data or page first.
- Report what you actually ran and saw; never invent results, sources or numbers.
- Ask before destructive, paid, public or irreversible actions.
- Never print, store or commit secrets or private personal data.

## Done when
Every item has an owner and backward-planned dates, weekly load fits stated capacity, buffers exist, and approved events or the table have been saved.
